作成: 2026-07-24（Fable 5 による設計。実装は Opus サブエージェントが本書に従って行う）

今回は理由が特定されている。対処すべきは「コンテンツの有用性・独自性・ナビゲーション」（Google 公式ヘルプが挙げる Low value content の3要素）に絞られる。

## 1. 診断 — なぜ「有用性が低い」と判定されるか（2026-07-24 実測）

### 1.1 記事の密度不足【最重要】
- 16本の本文合計 約17,500字 = **平均約1,100字/本**。全記事が「見出し3-4節×2段落」の均一構造。
- **数値例・表・図・歴史的事例・外部出典がゼロ**（guides.ts 内の外部リンク数: 0 / サイト全体で `<img>` 0件・図解SVG 0件）。
- 抽象的な心構え論のみで構成されており、「AI量産テキスト」の典型パターンに一致する。**長さより具体性の欠如が本質**。

### 1.2 唯一無二の資産（教え100件）が死蔵されている
- 「タルムード×金融解釈」はウェブ上に競合がほぼない独自コンテンツだが、**1URL に100件羅列**でインデックス上は1ページ分の価値しかない。
- 教えと記事が相互リンクしておらず、サイトのテーマ的一貫性が伝わらない。

### 1.3 情報設計（IA）が「データサイト」に見える
- 下部タブは 今日/マーケット/教え一覧 の3つ。**主力コンテンツの記事(/guides/)がメインナビに無い**（フッターのみ）。
- 審査員の初見: トップ=市況ダッシュボード → 「自動取得データ主体のサイト」の印象。
- パンくず・構造化データなし（`application/ld+json` 0件）。

### 1.4 視覚素材ゼロ
- 図解・表・画像が一切ない金融教育サイトは不自然で、制作労力のシグナルが弱い。

### 1.5 一括公開パターン
- 記事の日付が短期間に集中。今後の追加は段階公開に切り替える。

---

## 2. 設計原則（全実装がこれに従う）

1. **具体 > 抽象**: すべての主張に「数字・表・図・事例」のいずれかを添える。
2. **独自性の構造化**: タルムードの視点を全記事の固定セクションにする（飾りではなく骨格）。
3. **誠実さ**: 出典が趣旨・意訳のものは明記。断定しない。投資助言ではなく学習。事実（歴史的水準等）は一般に知られた概数のみを使い、不確かな数値は書かない。
4. **E-E-A-T**: 公開日+更新日の併記、著者表記、権威ある外部情報源（金融庁・日本銀行・JPX・投資信託協会・CBOE等）への参照リンク。
5. **段階公開**: 新規ページはまとめて出さず週単位で追加する。

## 4. Phase 1 仕様（構造）

### 4.1 ナビゲーション
- 下部タブを4つに: **今日 / マーケット / 記事 / 教え**（「記事」→ `/guides/`）。
- `Layout.astro` の `currentTab` 型に `"guides"` を追加。`/guides/` 配下の全ページで `currentTab="guides"` を渡す。

### 4.2 パンくず（記事ページ）
- 表示: ホーム > 市場の読み方 > {記事名}。`BreadcrumbList` JSON-LD を併設。

### 4.3 JSON-LD
- `Layout.astro`: `WebSite` + `Organization`（name: 賢者の金融市場, url, founder: `Person`「AI日本の裏側」）を全ページに出力。
- `guides/[slug].astro`: `Article`（headline / description / datePublished / dateModified / author: Person「AI日本の裏側」/ publisher）。
- Astro では `<script type="application/ld+json" set:html={JSON.stringify(obj)} />` で出力する。

### 4.4 ホーム再編（コンテンツ優先）
- セクション順を「教えカード → 記事セクション → 市況サマリー → 主要指標」に変更。

### 4.5 マーケットページの編集解説
- ページ冒頭に「このページの使い方」(150字程度)。
- 各カテゴリ見出し直下に2〜3文の「このカテゴリの見方」+ 関連記事リンク（日本株→what-is-nikkei、為替→dollar-yen/interest-rate-fx、商品・マクロ→vix-fear-index/yield-curve 等）。

### 4.6 404ページ
- `web/src/pages/404.astro`（トップ/記事/教えへの導線付き）。GitHub Pages は 404.html を自動配信する。

### 4.7 日付の整備
- `GuideArticle` 型に `published` を追加。実際の初公開日を正直に設定: 初期4本 = 2026-06-11、追加12本 = 2026-07-01。
- 記事ページと一覧に「公開日 / 最終更新」を併記。深化した記事は `updated` を実施日に更新する。

**受け入れ基準**: 全 .astro が @astrojs/compiler transform でエラーなし / 全ページに WebSite JSON-LD / 記事に Article + BreadcrumbList / タブ4つ / 404 生成 / published 表示。

## 5. Phase 2 仕様（パイロット4記事の深化ブリーフ）

### 共通フォーマット（深化後の全記事が満たすこと）
- 冒頭リード(150-200字) + **目次**（節へのアンカーリンク。sections から自動生成）
- 本文 **2,800字以上**、**表2点以上（または表1+図1以上）**、**図解SVG 1点以上**
- 固定セクション **「タルムードの視点」**（関連する教えに言及し、Phase 3b 公開後に相互リンク）
- **FAQ 3問**（各150-250字）
- **「参考情報」**: 権威ある外部リンク1-2本（金融庁 / 日本銀行 / JPX / 投資信託協会 / CBOE 等の実在する恒久的ページ。リンク切れしやすい深い階層は避け、トップor主要セクションへ）
- 図解SVGはインライン記述・`var(--text)` 等のCSS変数を使用（ライト/ダーク両対応）・外部画像なし
- データ構造: `guides.ts` の `sections` に `table`/`figure`/`faq` を表現できるよう型を拡張してよい（例: `blocks` 配列に `{type:"p"|"table"|"svg"|"faq"}`）。実装者が最も保守しやすい形を選ぶこと。

## 9. Phase 5 — 3回目却下（2026-08-28）を受けた構造転換

### 9.1 3回目却下の事実と再診断

Phase 1〜3b を完了し全16記事（2,800字超・表32点・図16点・FAQ48問・出典32本）＋教え個別10ページを公開、インデックスも良好（「クロール済み-未登録」0件）な状態で申請したが却下。メール文面は前回と同一。

**実測で判明した見落とし（2026-08-29）**:

| ページ | 総テキスト | 数値記号の割合 | 問題 |
|---|---|---|---|
| トップ `/` | **1,387字** | 20.3% | 審査員が最初に見る「サイトの顔」が薄い |
| `/market/` | 4,751字 | **34.2%** | 実体は Yahoo Finance（**非公式API**）から取得した77銘柄の価格一覧＝他者データの転載 |
| `/teachings/` | 13,304字 | 4.1% | ここは問題なし |

**再診断**: Phase 1〜3b は「記事の質・量」という一つの軸だけを2回続けて強化した。しかし AdSense の「価値の低い広告枠」は、コンテンツ不足だけでなく**他者コンテンツを主体とするページ・自動生成コンテンツ**も含む。審査員がトップ→マーケットと辿ったとき、サイトの第一印象は依然として「市場データを転載するサイト」のままだった可能性が高い。記事はサイトの奥にあり、入口が主張していなかった。

加えて、サイトは公開から約3ヶ月・検索流入はほぼ無い段階であり、AdSense は新規かつ無トラフィックのサイトに厳しい傾向がある。**構造の問題と時間の問題の両方に手を打つ**のが Phase 5 の狙い。

### 9.2 方針

**サイトの主体を「データ転載」から「読み物」へ移す。** 市場データ機能は残すが、検索・審査の対象からは外し、サイトの顔を学習コンテンツにする。

### 9.3 Phase 5-1 仕様（構造転換・即時実装）

**2. トップページ `/` を読み物中心に再構成し 3,000字以上へ**

セクション順:
