## 0. 事前準備

### 必要なもの
- [ ] Android 実機（min SDK 24 / Android 7.0 以降）
- [ ] Android Studio + adb（インストール用）
- [ ] USB ケーブル または無線デバッグ環境
- [ ] 安定した Wi-Fi または 4G/5G 回線

### 事前のコード状態確認
レビューで以下の改善が適用済みであることを確認:
- [ ] `MarketViewModel.kt`: 全銘柄失敗時に「通信に失敗しました」を errorMessage に設定
- [ ] `HomeViewModel.kt`: 同上の処理を追加
- [ ] `RetryInterceptor.kt`: 5xx/IOException で最大3回リトライ

### ビルドとインストール
1. Android Studio で `TalmudFinance` プロジェクトを開く
2. メニュー: **Build → Make Project**（エラー0件を確認）
3. メニュー: **Run → Run 'app'**（実機を選択）
4. アプリが起動し、ホーム画面が表示されることを確認
5. （オプション）logcat フィルタ「talmudfinance」「OkHttp」を起動しておく

## 2. シナリオ詳細

### S1: 機内モード ON 状態で初回起動

**目的**: ネットワーク完全断の状態でクラッシュせず、適切なフォールバックUIが出るか確認。

**手順**
1. 端末の機内モードを **ON** にする
2. 念のため Wi-Fi も OFF にする
3. TalmudFinance を **完全終了**（タスクから削除）
4. アプリアイコンから再起動

**期待動作**
- ✅ アプリが起動し、ホーム画面が表示される
- ✅ 「今日のタルムードカード」は表示される（アセットから読込のため）
- ✅ 市場サマリーは空（または「市場データを取得できませんでした」表示）
- ✅ エラー文言として「市場データを取得できません。通信状態を確認してください。」がホーム下部に表示される
- ✅ クラッシュなし、ANR（アプリ無応答）なし
- ⏱ ロード完了まで **約 7 秒以内**（リトライ × 並列のため）

**チェック欄**

| 項目 | OK/NG | 備考 |
|------|-------|------|
| クラッシュしない | ☐ | |
| ANR ダイアログが出ない | ☐ | |
| 教えカードは正しく表示 | ☐ | |
| エラー文言が表示 | ☐ | |
| ロード時間が許容範囲 | ☐ | 実測: ____秒 |

### S2: アプリ起動中に機内モード ON にする

**目的**: アプリが正常稼働中にネットワーク断が発生してもクラッシュしないこと。

**手順**
1. ネットワーク接続 OK の状態でアプリを起動
2. データが正常に表示されることを確認
3. 通知センター（スワイプダウン）から **機内モード ON**
4. アプリに戻る
5. マーケットタブの「再読込」ボタンを押す

**期待動作**
- ✅ クラッシュしない
- ✅ 再読込で「通信に失敗しました。ネットワーク接続を確認してください。」が表示
- ✅ 既存表示データはクリアされない（または明示的にエラー画面）

**チェック欄**

| 項目 | OK/NG | 備考 |
|------|-------|------|
| クラッシュしない | ☐ | |
| 再読込でエラー表示 | ☐ | |
| 既存データのハンドリング適切 | ☐ | |

---

### S3: 機内モード中の手動更新

**目的**: 全画面（ホーム/マーケット）の再読込ボタンが期待通り動くこと。

**手順**
1. 機内モード ON のまま
2. ホーム画面 → 右上の更新アイコンをタップ
3. マーケット画面 → 右上の更新アイコンをタップ
4. 各カテゴリタブ（日本株/米国株/為替/暗号資産）を切替

**期待動作**
- ✅ ローディング表示が出る → 数秒後にエラー文言に切替
- ✅ 連続タップしてもクラッシュなし
- ✅ タブ切替してもクラッシュなし

**チェック欄**

| 項目 | OK/NG |
|------|-------|
| ホーム更新で適切な挙動 | ☐ |
| マーケット更新で適切な挙動 | ☐ |
| 全カテゴリタブで挙動同じ | ☐ |
| 連打で問題なし | ☐ |

### S4: 機内モード OFF → 自動復帰（最重要）

**目的**: ネットワーク復活時にアプリが自発的に立て直すか、ユーザー操作で復活できるか確認。

**手順**
1. 機内モード ON でアプリ起動、エラー状態を確認
2. 通知センターから機内モード **OFF**
3. ネットワーク接続マークが出るまで5〜10秒待機
4. アプリ画面で右上の **再読込ボタン** をタップ

**期待動作**
- ✅ 再読込で完全にデータ取得成功
- ✅ エラー文言が消える
- ✅ 「最終更新: HH:MM:SS」が現在時刻に更新
- ⚠ 自動復帰（ボタン押さなくても自動取得）は **現在未実装**。これは想定動作

**チェック欄**

| 項目 | OK/NG | 備考 |
|------|-------|------|
| 復帰後の再読込が成功 | ☐ | |
| エラー文言が消える | ☐ | |
| 最終更新時刻が更新 | ☐ | |

### S5: Wi-Fi/モバイルデータ切替

**目的**: 接続切替の隙間（瞬断）でクラッシュしないこと。

**手順**
1. Wi-Fi 接続でアプリ起動、データ取得成功を確認
2. Wi-Fi を OFF、モバイルデータを ON
3. すぐにアプリで再読込

**期待動作**
- ✅ クラッシュなし
- ✅ モバイルデータでデータ取得成功（または再試行で成功）
- ✅ RetryInterceptor により短時間の瞬断は内部で解決

**チェック欄**

| 項目 | OK/NG |
|------|-------|
| 切替直後のクラッシュなし | ☐ |
| 再読込で成功 | ☐ |

---

### S6: バックグラウンド遷移 → 機内モード → 復帰

**目的**: プロセス保持中の状態遷移に耐えること。

**手順**
1. アプリ起動、データ取得成功
2. ホームボタンで **バックグラウンドに移動**
3. 設定画面から機内モード **ON**
4. 1分待機
5. 機内モード **OFF**
6. アプリに戻る（タスク切替）

**期待動作**
- ✅ State が保持されている（以前のデータが見える）
- ✅ 再読込ボタンで取得成功
- ✅ クラッシュなし

**チェック欄**

| 項目 | OK/NG |
|------|-------|
| State 保持 | ☐ |
| 再開後にクラッシュなし | ☐ |
| 再読込で成功 | ☐ |

### S7: 画面回転中の機内モード切替

**目的**: Activity 再構成中のクラッシュリスク確認。

**手順**

2. ロード中（CircularProgressIndicator 表示中）に端末を回転
3. 同時に通知バーから機内モード切替

**期待動作**
- ✅ クラッシュなし
- ✅ 回転後も状態が保持される
- ✅ Coroutine がリークしない（logcat に該当エラーなし）

**チェック欄**

| 項目 | OK/NG |
|------|-------|
| 回転でクラッシュなし | ☐ |
| Coroutine リークなし | ☐ |

### S8: タブ切替時のエラー伝播

**目的**: 一つの画面のエラー状態が他画面に悪影響しないこと。

**手順**
1. 機内モード ON でアプリ起動
2. ホームでエラー表示を確認
3. マーケットタブへ切替
4. 教え一覧タブへ切替（これは完全にローカルなのでエラーなし期待）
5. 各タブを往復

**期待動作**
- ✅ 教え一覧は機内モードでも完全表示（アセット読込のみ）
- ✅ ホーム/マーケットは各々独立してエラー処理
- ✅ クラッシュなし、フリーズなし

**チェック欄**

| 項目 | OK/NG |
|------|-------|
| 教え一覧はエラーなく表示 | ☐ |
| 各タブ独立に振る舞う | ☐ |
| 切替でクラッシュなし | ☐ |

### S9: 長時間放置（10分）後の復帰

**目的**: 長時間バックグラウンド後にプロセスが復活して正常動作すること。

**手順**

**期待動作**
- ✅ プロセスが死んでいてもタスク復帰で再起動
- ✅ 再起動後の初回読込が成功
- ✅ savedInstanceState による state 保持（現実装では未対応のため、初期化からスタートでOK）

## 3. 全シナリオ完了後の判定

### ゲート達成基準（Phase 2 #024）

以下を **すべて** 満たした場合に #024 を ✅ 完了とする:

- [ ] S1, S2, S4 （最重要 ★★★）すべて OK
- [ ] S3, S5, S6, S8（★★）で OK が 4 件中 3 件以上
- [ ] **クラッシュ・ANR が 1 件もない**
- [ ] エラーUIに「通信に失敗しました」または同等の文言が表示される

### 不合格時の対応

- クラッシュ → logcat の stack trace を控え、`docs/BUGS.md`（新規作成）に記録
- ANR → CPU/メモリ使用状況を控える
- 文言の問題 → コード修正で対応可
