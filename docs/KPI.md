# TalmudFinance KPI 設計

> 「測れないものは改善できない」。ただし測りすぎは害なので最小限に。
> 各フェーズで見るべき指標を明確にし、毎週金曜に1行だけ実績を追記する。

---

## 1. 北極星指標 (North Star Metric)

**「7日間以内に4回以上アプリを開いたアクティブユーザー数 (WAU 4+)」**

理由: 「毎朝開く習慣化」がプロダクトの本質。総ダウンロード数ではなく継続利用を北極星にする。

---

## 2. フェーズ別 KPI

### Phase 2（品質強化）

開発側の品質指標が中心。ユーザー指標はまだ追わない。

| 指標 | 目標 | 計測方法 |
|------|------|---------|
| ユニットテスト coverage | ≥ 50% | jacoco レポート |
| クラッシュ再現率（手動探索） | 0件/週 | QA帽子で週1回ランダムテスト |
| 教えの件数 | ≥ 100 | talmud_teachings.json 行数 |
| Yahoo API 失敗率 | ≤ 5% | OkHttp ログから手動集計 |

### Phase 3（リリース）

ユーザー獲得の初期指標を追加。

| 指標 | 目標 | 計測方法 |
|------|------|---------|
| インストール数（初週） | ≥ 50 | Play Console |
| インストール数（初月） | ≥ 200 | Play Console |
| クラッシュフリー率 | ≥ 99% | Firebase Crashlytics |
| Play Store 評価 | ≥ 4.0 | Play Console |
| 翌日継続率 (D1) | ≥ 40% | Firebase Analytics |

### Phase 4（機能拡張・習慣化）

北極星指標と通知効果を追う。

| 指標 | 目標 | 計測方法 |
|------|------|---------|
| **WAU 4+（北極星）** | ≥ 200 人 | Firebase BigQuery |
| 7日継続率 (D7) | ≥ 30% | Firebase Analytics |
| 30日継続率 (D30) | ≥ 15% | Firebase Analytics |
| 通知許可率 | ≥ 50% | Firebase Analytics |
| 通知タップ → 開封率 | ≥ 25% | Firebase Analytics |
| 1セッション平均滞在時間 | ≥ 30秒 | Firebase Analytics |

## 4. 「測らない」と決めたこと

意図的に追わないことで、判断のシンプルさを保つ。

- **総ダウンロード数の絶対値** — バニティ指標。WAU4+ を見る
- **ストアレビュー個別の感情的反応** — 集計値のみ見る（教え #18）
- **競合アプリの DL 推移** — 比較は害が大きい（教え #10）
- **収益** — Phase 4 までは追わない（教え #6）

---

## 5. 失敗判定（フェーズ撤退条件）

以下に該当したら、機能追加よりも撤退/ピボットを検討する:

- Phase 3 完了後3ヶ月で月間アクティブユーザーが10人未満
- クラッシュフリー率が連続2週で 95% を下回る
- 自分自身が1ヶ月開いていない（プロダクトオーナー離脱は致命）
